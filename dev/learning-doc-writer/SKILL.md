# 学习文档生成

这个 skill 用于把一个新知识整理成适合初学者复习的学习文档。重点不是“写得完整”，而是让读者知道每个概念是什么、为什么需要、怎么用，以及容易卡在哪里。

## 触发场景

- 用户要求学习一个新知识并生成文档。
- 用户要求整理学习笔记、教程、Markdown 文档。
- 用户要求把某个概念讲清楚，并沉淀成可复习的材料。
- 用户在学习 JS、前端、工具、框架、通用技术概念时，需要一篇从零开始的说明。

## 不适用场景

- 代码审查、缺陷风险、回归检查：使用 `dev-code-review`。
- 阅读某段具体代码、梳理代码执行流程、解释输入到输出：使用 `dev-code-learning`。
- 只需要一句话回答或临时解释时，不必强行生成完整文档。

## 默认流程

1. 先判断学习对象和读者阶段。
2. 先给一句主线：这篇文档到底帮读者解决什么困惑。
3. 标题必须说人话，避免把术语直接当标题。
4. 复杂概念拆成轻量小节，例如 `3.1 / 3.2 / 3.3`。
5. 每个知识点按这个顺序写：`是什么 -> 为什么需要 -> 怎么写 -> 最小例子 -> 常见误区`。
6. 多个容易混淆的概念必须分开讲，例如表达式和语句、数组和对象、状态和普通变量。
7. 最后补学习建议、回看导航和小结。

## 文档结构

默认使用下面结构，可根据材料多少删减：

```text
# 标题

## 问题背景
这篇文档解决什么学习困惑。

## 核心解释
按概念拆小节讲清楚。

## 技术关系
它和已经学过的内容是什么关系。

## 学习建议
卡在哪里时回看哪一节。

## 小结
用几句话收束主线。
```

## 写作规则

- 默认用中文。
- 面向初学者，不端着，不堆术语。
- 优先短句和真实例子。
- 不为了完整而扩写太多。
- 如果标题读起来像教材，要改成人话。
- 如果一节里混了多个概念，要拆成子节。
- 如果用户已经有原文，只优化结构和解释，不随便扩展新主题。
- 小标题层级要轻，必要时用 `##### 3.1 ...` 这种小标题，不要让页面显得太重。

## 标题写法

优先这样写：

```text
函数：把一段逻辑包起来
表达式和语句：一个算值，一个做事
对象：用 {} 描述一组数据
数组：保存列表，配合方法更新列表
```

避免这样写：

```text
函数声明、函数表达式、回调函数
表达式和语句：自动 return、JSX 里的 {}
对象字面量、返回对象为什么写 ({})
```

## 输出约束

- 先给主线，再展开细节。
- 先讲“是什么”，再讲“为什么”，最后讲“怎么用”。
- 示例要小而具体，优先贴近用户正在学的上下文。
- 结尾给回看导航或学习建议，帮助用户知道卡住时看哪里。
